# 产品功能需求清单

这份文档用于统一 `tweet-db` 的产品范围、功能目标和业务规则，供后续需求确认、页面设计和功能拆分使用。本文聚焦产品角色、用户体验和业务行为。

## 1. 产品定位

- `tweet-db` 是围绕 X 帖子建立的中心化内容库、同步状态中心和受管媒体资源库。
- 系统服务四类协作主体：`x-monkey` 同步脚本、登录用户、管理员、媒体转储工作者。
- 首版产品价值集中在三件事：沉淀帖子内容、确认同步状态、把可用媒体转储为受管 OSS 资源。

## 2. 核心业务对象

- 帖子：系统围绕帖子保存正文、作者、会话关系、统计信息、可见性和同步状态。
- 媒体：系统围绕帖子媒体保存基础信息、原始来源、转储状态、受管资源与引用关系。
- 资源文件：系统围绕 OSS 文件保存文件身份、资源位置、来源链路、当前状态与关联对象。
- 用户账户：系统围绕登录用户和管理员保存身份、角色、可用状态与操作范围。

## 3. 功能范围

### 3.1 账号与身份管理

- 用户通过统一登录进入系统，并完成本地账号绑定。
- 系统提供登录用户与管理员两级角色。
- 管理员可以查看用户列表、查看用户详情、停用账号、恢复账号。
- 账号状态直接影响登录可用性与后台访问范围。
- 关键身份动作进入审计记录。

### 3.2 与 `x-monkey` 的同步协同

- `x-monkey` 可以检查单条帖子的远端同步状态。
- `x-monkey` 可以提交单条帖子信息。
- `x-monkey` 可以提交批量帖子信息。
- 同步状态覆盖帖子、作者、媒体三个层面，并形成统一结果视图。
- 同步结果包含收录情况、差异情况、失败原因和权限状态。
- 当用户需要登录或完成账号绑定时，脚本可以把用户引导到站内账号入口。

### 3.3 帖子内容库

- 系统为登录用户提供帖子列表与帖子详情。
- 帖子列表支持围绕时间、作者、同步状态和可见性进行浏览与筛选。
- 帖子详情展示正文、作者信息、会话关系、媒体内容、同步状态和可见性结果。
- 帖子与作者、媒体之间保持可追溯关联。

### 3.4 帖子可见性管理

- 系统为帖子提供可见性字段。
- 管理员可以修改帖子可见性。
- 帖子可见性直接控制普通登录用户在列表、详情和关联媒体中的可见范围。
- 可见性调整进入审计记录。

### 3.5 媒体转储队列

- 系统在媒体进入内容库后创建转储任务。
- 转储任务以媒体来源 URL 为输入，经过内存缓冲区完成下载与上传。
- 队列围绕媒体资源进行去重、排队、执行、重试和状态更新。
- 转储任务具备待处理、处理中、已完成、失败四类业务状态。
- 转储失败会保留失败原因，供管理员查看和再次处理。
- 转储完成后，系统把受管 OSS 资源纳入前端展示和后台管理。

### 3.6 OSS 媒体资源管理

- 系统提供独立的媒体资源管理域，用于管理媒体对象与 OSS 文件。
- 媒体资源管理围绕三个层次展开：媒体对象、转储任务、OSS 文件。
- 管理员可以查看资源列表、查看资源详情、查看引用帖子、查看当前文件状态。
- 管理员可以重试转储、刷新资源状态、调整资源可见性、处理失效资源。
- 资源详情记录原始来源地址、当前受管地址、任务状态、关联帖子和更新时间。
- 首版资源管理以帖子媒体为核心资源类型。

### 3.7 前端产品体验

- 系统提供一个 Vue 前端作为统一入口。
- 登录用户进入后可以浏览帖子、查看帖子详情、查看已转储完成的媒体。
- 登录用户可以看到与自己访问范围相关的同步结果和资源状态。
- 管理员拥有额外的管理后台入口。
- 管理后台覆盖帖子可见性管理、媒体资源管理、转储任务查看、用户身份管理。
- 帖子页面与媒体资源页面之间提供双向跳转。

### 3.8 媒体展示规则

- 登录用户优先查看已经转储完成的受管媒体资源。
- 转储中的媒体展示处理中状态。
- 转储失败的媒体展示失败状态和基础说明。
- 管理员可以同时查看原始来源与受管资源状态。

## 4. 页面清单

- 账号入口页：承载登录、注册绑定、当前会话信息。
- 帖子列表页：承载浏览、筛选、同步状态概览。
- 帖子详情页：承载帖子内容、作者信息、媒体展示、同步状态。
- 管理员帖子页：承载帖子可见性管理和帖子级治理动作。
- 管理员媒体资源页：承载资源列表、资源详情、引用关系与转储状态。
- 管理员转储任务页：承载任务列表、失败原因、重试动作。
- 管理员用户页：承载用户列表、用户详情、启用停用动作。

## 5. 角色能力边界

- 登录用户拥有浏览帖子、查看详情、查看已转储媒体、查看与自己可见范围一致的状态信息的能力。
- 管理员拥有登录用户全部能力，并额外拥有帖子治理、资源治理、任务处理、用户管理能力。
- `x-monkey` 拥有状态检查和帖子提交能力。
- 媒体转储工作者拥有队列消费、媒体转储、任务状态更新能力。

## 6. 首版业务规则

- 帖子同步状态围绕帖子、作者、媒体三个维度汇总。
- 帖子进入系统后，相关媒体进入资源管理域。
- 资源进入资源管理域后，系统生成对应转储任务。
- 转储完成的资源进入普通登录用户视图。
- 管理员对帖子和资源的治理动作即时影响前端可见结果。
- 账号停用即时影响系统访问范围。

## 7. 首版完成标准

- 登录用户可以顺畅完成登录并浏览帖子与已转储媒体。
- `x-monkey` 可以完成帖子同步状态检查和帖子信息提交。
- 系统可以把媒体 URL 排入队列并转储到 OSS。
- 管理员可以完成帖子可见性管理、媒体资源管理、用户身份管理。
- 整个系统形成“采集提交 -> 状态确认 -> 媒体转储 -> 前端展示 -> 管理治理”的完整闭环。
